3. Enroll, start and stop

Windows administrator install — enrollment, status and removal

The administrator script installs for all users and starts the “Orbitus ViperLink Cloud” task as LocalService. It starts at boot without a login. The task is visible in Windows Task Scheduler. A one-minute recovery trigger restarts a stopped receiver and leaves an existing running instance alone. Private enrollment remains explicit.

  1. Stop any existing receiver using the same profile, including RedAgent. Preserve its journal when migrating.
  2. Place receiver.json, fleet-private.pem and any existing journal in %ProgramData%\Orbitus\ViperLink. The installing operator and administrators have access; ordinary users do not.
  3. Set the profile’s shared root to C:\ProgramData\Orbitus\ViperLink\Workspace, or another folder accessible to LocalService. Review the interval and set enabled=true when ready.
  4. Read startup-status.json in that directory for waiting-for-enrollment, disabled, checked-in or check-in-failed. Verify the authenticated receipt for actual job delivery.

To stop: disable the task in Task Scheduler and end its running instance. To remove: delete that task and %ProgramFiles%\Orbitus\ViperLink. Preserve or revoke enrollment separately. The receiver runs with LocalService permissions; installing it as administrator does not make every remote command an administrator command.

Cloud Fleet user install — foreground receiver
  1. Use the Fleet administrator toolkit to enroll a unique machine. Keep its receiver.json and fleet-private.pem in a private directory outside this installation.
  2. Review its shared folder and 1–1,440 minute interval. Create the shared directory, then deliberately set enabled to true in the private profile.
  3. In the installed component directory, run the foreground receiver below. Replace the profile path with your own absolute path; use a quoted Windows path on Windows.
node queue-agent.mjs --profile /absolute/private/receiver.json --watch

Use --once for one check-in. Ctrl+C stops the process; enabled=false prevents the next start. The user installer adds no service or login item. Keep only one receiver per profile, including RedAgent. Verify the authenticated receipt after queueing a job.

The Fleet transport key grants access to fleet records and belongs only on trusted managed machines. Per-machine keys protect command contents and receipts. CloudKit production activation remains separate from this pilot.

Status reporting only — send a report you prepare

Obtain the private reporting profile through the Fleet toolkit, prepare truthful status JSON, and validate locally from the installed directory:

node report-direct.mjs --profile /absolute/private/reporter-profile.json --report /absolute/status.json --validate

Omit --validate to send. The process exits after one report. This package does not include the command receiver or collect an application inventory. The reporting credential has fleet record access; package selection does not narrow that credential’s CloudKit permissions.

LAN / VPN controller — control an existing ViperLink host

Start an existing native ViperLink host and provision a private controller profile there. Place the profile on this machine and run from the installed directory:

python3 viperlink.py --profile /absolute/private/controller.json clients

On Windows use python and a quoted Windows path. Use --help for commands and choose the target explicitly. This Python tool is a controller; it does not turn Windows or Linux into a LAN execution target. The native Mac host and native Mac/iOS apps remain separate development builds. Choose Cloud Fleet commands when this machine should receive jobs.

Install locations, upgrades and removal

macOS: ~/Library/Application Support/Orbitus/ViperLink
Linux: ~/.local/share/Orbitus/ViperLink
Windows: %LOCALAPPDATA%\Programs\Orbitus\ViperLink

Each component has its own {{ $release.version }} directory. A repeat install verifies all packaged files and preserves unrelated directories; older versions remain intact. To remove a component, stop its foreground process and remove its versioned directory. Keep or revoke private enrollment separately. Removing installed files does not revoke a credential.
