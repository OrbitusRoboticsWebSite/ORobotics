The installer validates the native bundle's pinned SHA-256 before extraction.
It uses a same-filesystem staging directory, refuses unmanaged destination
collisions, retains a prior managed install during repair, and records the
source commit, archive checksum and mdmEnrolled=false. The existing app's
evidence directories are not deleted. Repeat installs of an intact launcher
with the same recorded bundle hash are no-ops (not a full integrity audit).

macOS/Linux options: --dry-run, --prefix ABSOLUTE_PATH, --archive PATH.
Windows options: -DryRun, -InstallDir ABSOLUTE_PATH, -ArchivePath PATH,
-Scope User|Machine, and -ControlUser SID for the administrator machine install.
The normal paths install for the signed-in user. Run in that user's session,
not a root/SYSTEM context. Windows adds a Start Menu shortcut. Then open
Cloud Fleet > Install system helper and complete the platform's administrator
authorization. The user installer does not elevate or start a service. The
separate Windows administrator command requests normal UAC approval and installs
for all users plus the automatic LocalService helper, starting it immediately.

Optional scanning/capture engines and drivers are not included. The installer
does not start the desktop app, a scan, or a wireless operation. Only the explicit
Windows administrator path starts the background helper during installation.
No system security or PowerShell execution policy is changed. Existing MDM
policy can prevent unsigned scripts/apps. Production distribution requires
appropriate signing and validation before broader corporate rollout.

Flipper files are generated from the same command data as the page. Upload
the .txt files to SD Card/badusb/, select OS, choose USB mode and keyboard
layout, connect to the unlocked desktop, and press Run. Linux assumes a
Ctrl+Alt+T terminal shortcut. Timing/focus and first-use prompts need physical
validation. Standard Flipper firmware does not run the script solely because
the cable was connected. No device ID spoofing or policy bypass is used.

Cloud Fleet 0.4 and persistent execution:
- launchd LaunchDaemon on macOS, automatic Windows Service, systemd on Linux.
- All GUI execution, inventory, campaign queues, Cloud Fleet check-ins and saved
  job results belong to the machine helper. GUI closure leaves them running.
- macOS runs as the installation account; Windows uses LocalService; Linux uses
  the configured unprivileged account. Other users do not automatically gain
  control access. Inputs must be readable by that fixed service account.
- Python/Tk and a verified, pinned Node.js 22 runtime are bundled. Keep the entire
  archive together; Windows/Linux need the adjacent RedAgentHelper directory.
- Private enrollment is imported separately. Public downloads have no keys.
  For 0.3 migration, disable/close the old receiver first and retain its journal.
- Choose a 1-1440 minute check-in interval (default five), enable cloud commands,
  and use Check in now, Disable cloud commands, or Stop job explicitly.
- The local control connection uses installation-specific TLS and a protected
  credential; it binds only to loopback and rejects browser-origin requests.
- Service installation, supervisor recovery after a forced crash, retained jobs,
  and uninstall were tested on all four native CI platforms. This does not claim
  physical reboot/logout, Windows 11 field testing, or hardware capture acceptance.
- System helper state is in /Library/Application Support/Orbitus/RedAgent,
  %ProgramData%\Orbitus\RedAgent, or /var/lib/redagent. Uninstall unregisters the
  service and preserves enrollment/evidence. Interrupted jobs never auto-replay.
- Sleep, disk unlock, shutdown and network loss constrain delivery. Cloud Fleet
  remains an application command channel, not a hosted Apple/Windows MDM server.
